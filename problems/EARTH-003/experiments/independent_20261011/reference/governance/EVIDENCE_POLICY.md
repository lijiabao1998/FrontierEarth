# 證據與宣稱

## 不用單一線性等級混合各學科
每項 claim 分別記：工作狀態、來源狀態、形式／計算證據、經驗證據、獨立重現、新穎性、範圍與限制。數學形式證明不會因此自動成為生物實驗支持；實驗相關性也不會變成數學證明。

| 類型 | 能支持 | 不能自動推出 |
|---|---|---|
| 文獻一致 | 與已讀資料相容 | 未解、正確、新穎 |
| 有限精確驗證 | 指定有限實例、證書或窮舉範圍 | 對所有 n 的定理 |
| 浮點模擬 | 在模型、離散化與數值誤差下的結果 | 嚴格存在證明、自然界機制 |
| Lean kernel | 被實際形式化的命題在所列公理下成立 | 自然語言目標翻譯正確、新穎、物理真實 |
| 統計支持 | 指定設計與資料下的估計、區間及穩健性 | 無條件因果、跨族群泛化 |
| 獨立實驗 | 在實驗條件下重現 | 超出條件的普遍完成 |

## 來源
每條引用：title、HTTPS URL/DOI/arXiv、kind、supports。另記版本、閱讀日期、全文或摘要、是否有修訂。只存自己的摘要、合法可重用資料與必要短引文，不整篇搬有版權文章。資料有自己的 license，文章開放不表示附件任意可用。來源不得是無法打開的虛構 DOI。

## 驗證器也被審核
凍結規格後建立正例、反例、邊界案例和至少一項故意破壞測試。獨立 reviewer 比對輸入／輸出／目標是否同一件事。不可讓產生候選的 agent 同 PR 偷改評分器、刪難例、換資料切分或放寬閾值。

## Lean
固定 Lean toolchain、mathlib revision（採用時）及 lake manifest。`lake build` 綠不代表無 sorry：檢查輸出警告與已匯出 claim 的 `#print axioms`。允許基礎公理範圍由卡面列明，預設只允許 propext、Classical.choice、Quot.sound；sorryAx、未批准自訂 axiom、額外原生信任來源拒絕。不要只 grep 字串當完整公理審計。即使公理乾淨，還要審命題是否被弱化、假設是否矛盾、答案是否藏在定義裡。

官方參照：
- https://lean-lang.org/doc/reference/latest/ValidatingProofs/
- https://lean-lang.org/doc/reference/latest/Axioms/
- https://github.com/leanprover/lean-action

## 經驗研究
訓練／驗證／測試依 donor、時間、機構、同源群或化學骨架適當分離；先登記效應指標與區間、多重比較、缺失資料及替代假設。不得看完測試集再改成功門檻。數值研究記單位、守恆、邊界、收斂和模型不確定性。形式工具只驗實際命題；owner approval 只代表治理批准。
